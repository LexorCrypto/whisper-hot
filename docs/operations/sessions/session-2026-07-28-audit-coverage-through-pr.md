### 2. Исправленные дефекты

**[P2] `AudioDeviceSwitchSmokeTests.swift` — маскировка тестов.** Коммит `8ed3633`
(предыдущая сессия) заменил `XCTAssertEqual(status, noErr, …)` безусловным
`guard status == noErr else { return kAudioObjectUnknown }`. Поскольку вызывающие тесты
делают `XCTSkipIf(systemDefault == kAudioObjectUnknown)`, **любая** ошибка CoreAudio
превращалась в зелёный пропуск обоих тестов — платформенный контракт, ради которого эти
смоук-тесты существуют, перестал проверяться.

Исправлено в `d14b363`: `requireDefaultInputDeviceID() throws` бросает
`CoreAudioQueryFailure` при любом ненулевом `OSStatus`; skip остаётся ровно для одного
исхода — успешный запрос, вернувший `kAudioObjectUnknown`.

`kAudioHardwareBadObjectError` **намеренно не внесён** в исключения: по заголовку SDK он
означает «переданный AudioObjectID не соответствует валидному AudioObject»
(`AudioHardwareBase.h:136-137`), а `kAudioObjectSystemObject` валиден всегда
(`AudioHardware.h:104-106`). Внести его в исключения значило бы сохранить ту же дыру под
другим именем.

**[P3] `SPEC.md:900`.** Утверждение «версии до `0.4.0` содержат только подраздел "Для
пользователей"» неверно: у `0.1.0`, `0.2.1`, `0.2.2`, `0.3.0` парный раздел для
разработчиков есть, он озаглавлен «Для контрибуторов»
(`CHANGELOG.md:924,971,1013,1154`). Отсутствует именно заголовок «Для разработчиков».

**[P3] ссылка на заголовок SDK** в докстринге теста указывала на
`AudioHardwareBase.h:136-137` в подтверждение валидности системного объекта — эти строки
документируют другое. Теперь приведены обе ссылки, каждая под своё утверждение.

**[P3] счётчики `ContextRouter` в `SPEC.md:914` и `:957`.** Пересчитано по коду:
production `ContextRouter.resolve` вызывается в 3 тестах из 15, а не в 2 — пропущен был
`testSlackMatchesCasual`, где результат вдобавок отбрасывается через `_ =` и ничего не
утверждает. Helper `resolveByBundleID` — в 12 тестах, а не в 13.

## Границы того, что доказано

Audit-запись — файл в репозитории: она подтверждает **топологию и целостность**
(диапазон резолвится, `tree` равен дереву `tip`, коммиты внутри диапазона), но **не
провенанс**. Любой, кто может коммитить, может написать парсящийся файл со словом `SHIP`.
Контроль — человеческий review audit-only коммита в PR плюс прогон предиката. Не
описывайте запись как доказательство того, что Codex действительно запускался.

Арбитр раунда 7 отдельно отметил, что не мог независимо подтвердить существование,
размеры и баннеры внешних stdout-журналов: они лежат вне выданного read-only дерева.
